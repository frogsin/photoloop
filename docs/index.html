现有工具的三个断点

The Problem
Why this exists
01 / 03

门槛太高

COLMAP 有上百个参数，光「匹配策略」就要判断该用穷举、顺序还是词袋。普通人拍完照片，不知道该点哪里。

02 / 03

失败不解释

重建失败时，程序要么直接崩溃、要么给出一句 0xC0000409。没有人告诉你：是你拍得不对，还是参数不对。

03 / 03

成品不可信

模型出来了，但满屏气泡、主体不见了。你不知道该重拍、该调参，还是该换工具。

04

最有价值的一个发现

Normal Orientation
Why the mesh failed
69.7%
法向方向原本是反的 · 36,638 / 52,553
# 用观测相机确定法向朝向 for p, n, cam in points: v = cam - p if dot(n, v) < 0: n = -n # 实测：69.7% 被翻转

点云是对的，网格却是碎的

Poisson 曲面重建有一个隐含前提：所有点的法向必须朝向一致。 但通用的法向估计算法（PCA）只能算出「方向」，算不出正负——每个点朝里还是朝外是随机的。

我们用 SfM 里现成的信息解决了它：每个三维点都是被某些相机观测到的， 把法向朝向观测它的相机，方向就唯一确定了。

校正前：主体被淹没在气泡里，包围盒 82.68。
校正后：轮廓与细节清晰，包围盒 8.56。

05

我们还没解决的问题

Known Limitations
Honest disclosure
[ 01 ]

帧冗余严重

264 张照片实际只分布在 5 个连拍簇里，平均轨迹长度 11.95（单物体重建通常 3–6）。大量近重复帧没有带来新的视角信息，只是浪费了计算。

[ 02 ]

稠密重建模块受限

COLMAP 4.2.1 的立体匹配在本机无法产出几何一致性深度图（参数无法生效且崩溃）。当前网格由稀疏点云直接重建，表面细节有限。

[ 03 ]

背景物被一起重建

实测中主体只占最终点云的 48%，其余是桌面与周围环境。曲面重建会跟随背景延展，导致物体被"压平"，主体还需要按颜色与空间进一步分割。

[ 04 ]

尚无图形界面

目前是命令行工具（scan check / report / cloud）。本页是成果展示，不是操作界面。可视化流水线是下一步工作。
